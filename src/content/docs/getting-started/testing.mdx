Build and test against the demo environment (`https://demo.ponchopay.com`). No real money moves
there. To place test orders and receive webhooks you need a demo account: ask your account manager
or email [support@ponchopay.com](mailto:support@ponchopay.com).

Each payment method must be turned on in your demo admin before you can test it.

## Trigger webhooks

First set your webhook URLs in the demo admin under
[Settings → API integration](https://demo.ponchopay.com/provider/admin/settings). To reach a server
on your laptop, use a tunnelling tool such as ngrok or Cloudflare Tunnel.

| Webhook                                                                      | How to trigger it on demo                                                                                                                                         |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`payment_captured`](/webhooks/events/payment-captured/)                     | Enter card details in checkout.                                                                                                                                     |
| [`payment_reported_complete`](/webhooks/events/payment-reported-complete/)   | Pay with Standard Tax-Free Childcare or vouchers and report the payment as complete in checkout.                                                                   |
| [`payment_completed`](/webhooks/events/payment-completed/)                   | Sent automatically once the payment has been marked as complete.                                                                                                   |
| [`payment_in_bank`](/webhooks/events/payment-in-bank/)                       | On the [payments page](https://demo.ponchopay.com/provider/admin/payments), use **Mark in bank** at the end of the row. Only completed payments can be marked.     |
| [`payment_refunded`](/webhooks/events/payment-refunded/)                     | [Refund a payment method](/endpoints/refund-payment-method/), or refund from the admin.                                                                            |
| [`payment_cancelled`](/webhooks/events/payment-cancelled/)                   | [Cancel the payment](/endpoints/cancel-payment/), or cancel it in the admin.                                                                                       |

## Before you go live

Run at least these tests, and check both the PonchoPay admin and your own system each time:

- [ ] A card payment. Check every webhook arrives and is handled.
- [ ] A Tax-Free Childcare payment. Check the webhooks.
- [ ] A childcare voucher payment. Check the webhooks.
- [ ] A voucher payment where the parent enters their card but doesn't finish checkout.
      `payment_completed` must not be sent.
- [ ] A Tax-Free Childcare payment where the parent enters their card but doesn't finish
      checkout. `payment_completed` must not be sent.
- [ ] Every payment appears in the PonchoPay admin, and PonchoPay's transactional emails arrive.
- [ ] Every payment appears in your system, and your own actions (such as confirmation emails)
      happen.

<Aside title="Switching to production">
  Change the base URL to `https://pay.ponchopay.com/api/` (with the SDKs, `https://pay.ponchopay.com/`),
  use your production integration key, and set your webhook and redirect URLs in the production
  admin.
</Aside>
