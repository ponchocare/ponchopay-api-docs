<ApiColumns>
  Everything is signed with your [integration key](/getting-started/introduction/#set-up-your-account),
  in one of three ways depending on what you're doing:

  | Used for | How it's signed |
  | --- | --- |
  | [Initiate a payment](/endpoints/initiate-payment/) and [Initiate a subscription](/endpoints/initiate-subscription/) | A [`token` field](#initiation-token) in the body |
  | [Validate location](/endpoints/validate-location/), [update](/endpoints/update-payment-method/), [refund](/endpoints/refund-payment-method/) and cancel endpoints | A [JWT](#management-jwt) in the `Authorization` header |
  | [Webhooks](/webhooks/overview/) PonchoPay sends you | A [`signature` header](#webhook-signatures) you check |

  The [Node.js](/sdks/nodejs/) and [PHP](/sdks/php/) SDKs create tokens and JWTs for you, and the
  Node.js SDK also verifies webhooks.

  <Aside type="danger" title="Keep your integration key on your server">
    Compute tokens on your server. Never put the integration key in browser code, a mobile app or a
    public repository.
  </Aside>
</ApiColumns>

## Initiation token

<ApiColumns>
  Requests that create a payment or recurring payment include a `token` field, computed from your
  integration key and the request's `metadata`:

  ```txt
  token = base64( sha256( metadata + "." + integrationKey ) )
  ```

  - `sha256` gives the raw digest (bytes, not hex).
  - `base64` is standard Base64, with padding.
  - The token changes with `metadata`, so compute one for each request.

  These requests can come from the browser (a form or the `<pp-payment>` web component). Compute
  the token on your server and render it into the page.

  <Fragment slot="code">
    <Tabs syncKey="lang">
      <TabItem label="Node.js">
        ```ts
        import { createToken } from '@ponchopay/pp-nodejs';

        const integrationKey = process.env.PONCHOPAY_INTEGRATION_KEY;
        const token = createToken(integrationKey, 'order-67651');
        ```
      </TabItem>
      <TabItem label="PHP">
        ```php
        <?php

        use function PonchoPay\createToken;

        $integrationKey = getenv('PONCHOPAY_INTEGRATION_KEY');
        $token = createToken($integrationKey, 'order-67651');
        ```
      </TabItem>
      <TabItem label="Python">
        ```python
        import base64, hashlib, os

        key = os.environ["PONCHOPAY_INTEGRATION_KEY"]
        metadata = "order-67651"
        digest = hashlib.sha256(f"{metadata}.{key}".encode("utf-8")).digest()
        token = base64.b64encode(digest).decode()
        ```
      </TabItem>
      <TabItem label="Shell">
        ```bash
        METADATA='order-67651'
        TOKEN=$(printf '%s' "$METADATA.$PONCHOPAY_INTEGRATION_KEY" \
          | openssl dgst -sha256 -binary | base64)
        ```
      </TabItem>
    </Tabs>
  </Fragment>
</ApiColumns>

## Management JWT

<ApiColumns>
  Endpoints that read or change existing payments expect a short-lived
  [JSON Web Token](https://datatracker.ietf.org/doc/html/rfc7519) in the `Authorization` header:

  ```http
  Authorization: Bearer <jwt>
  ```

  Sign it with **HS256**, using the raw SHA-256 digest of your integration key as the secret. Its
  payload has these claims:

  <Fields schema="JwtClaims" />

  Create a new token for each request, right before you send it, from the exact body you'll send.
  If you change the body after signing, `sig` won't match.

  <Aside title="Checking a token">
    Paste a token into [jwt.io](https://jwt.io) to see its claims. To check the signature, use
    `base64url(sha256(integrationKey))` as the secret and set the secret's encoding to base64url.
  </Aside>

  <Fragment slot="code">
    <Tabs syncKey="lang">
      <TabItem label="Node.js">
        ```ts
        import { createJWT } from '@ponchopay/pp-nodejs';

        const body = JSON.stringify({ amount: 1000 }); // '' for requests with no body
        const jwt = await createJWT(
          'INTTEST',                              // urn
          process.env.PONCHOPAY_INTEGRATION_KEY,  // integration key
          'admin@club.example.com',               // email
          body,
        );
        ```
      </TabItem>
      <TabItem label="PHP">
        ```php
        <?php

        use function PonchoPay\createJWT;

        $body = json_encode(['amount' => 1000]); // '' for requests with no body
        $jwt = createJWT(
            'INTTEST',                              // urn
            getenv('PONCHOPAY_INTEGRATION_KEY'),    // integration key
            'admin@club.example.com',               // email
            $body,
        );
        ```
      </TabItem>
      <TabItem label="Python">
        ```python
        import base64, hashlib, json, os, time
        import jwt  # PyJWT

        key = os.environ["PONCHOPAY_INTEGRATION_KEY"]
        body = json.dumps({"amount": 1000})  # "" for requests with no body
        now = int(time.time())

        token = jwt.encode(
            {
                "urn": "INTTEST",
                "email": "admin@club.example.com",
                "sig": base64.b64encode(hashlib.sha256(body.encode()).digest()).decode(),
                "iat": now,
                "exp": now + 5,
            },
            hashlib.sha256(key.encode("utf-8")).digest(),
            algorithm="HS256",
        )
        ```
      </TabItem>
    </Tabs>

    <Example schema="JwtClaims" title="Example JWT payload" />
  </Fragment>
</ApiColumns>

## Webhook signatures

<ApiColumns>
  Every webhook has a `signature` header: the HMAC-SHA256 of the raw request body, using your
  integration key, encoded as URL-safe Base64 without padding. Check it before you trust the body.

  See [verify and handle webhooks](/webhooks/overview/#verify-and-handle-webhooks) for code in
  each language.

  <Fragment slot="code">
    ```txt
    signature = base64url( hmac_sha256( key = integrationKey, message = rawBody ) )
    ```
  </Fragment>
</ApiColumns>
