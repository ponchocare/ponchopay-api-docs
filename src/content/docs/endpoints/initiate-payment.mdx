<ApiColumns>
  Creates a payment for one of your locations and redirects to its PonchoPay checkout. The
  response is a `302` redirect: the `Location` header is the checkout URL to send the parent to.

  You can call it in two ways:

  - **From your server.** Your server makes the request, reads the `Location` header and
    redirects the parent there. This is what the Node.js and PHP SDKs do.
  - **From the browser.** Your page posts a form straight to this URL and the browser follows the
    redirect. Use the [`<pp-payment>`](/sdks/browser/#pp-payment)
    web component or a plain HTML form. Your server still has to compute the `token`.

  <Aside type="danger" title="Keep your integration key on your server">
    The `token` is computed from your integration key. Always compute it on your server. Never put
    the integration key in browser code, a mobile app or a public repository.
  </Aside>

  <Fragment slot="code">
    <Endpoint method="POST" path="/api/integration/generic/initiate" />
  </Fragment>
</ApiColumns>

## Authentication

<ApiColumns>
  Every request includes a `token` field, computed from your
  [integration key](/getting-started/introduction/) and the request's `metadata`:

  ```txt
  token = base64( sha256( metadata + "." + integrationKey ) )
  ```

  The hash is the raw SHA-256 digest (bytes, not hex), encoded with standard Base64. Because the
  token depends on `metadata`, compute a new one for each payment. The SDKs' `initiatePayment`
  does this for you.

  <Fragment slot="code">
    <Tabs syncKey="lang">
      <TabItem label="Node.js">
        ```ts
        import { createToken } from '@ponchopay/pp-nodejs';

        const integrationKey = process.env.PONCHOPAY_INTEGRATION_KEY;
        const token = createToken(integrationKey, 'order-67651');
        ```
      </TabItem>
      <TabItem label="PHP">
        ```php
        <?php

        use function PonchoPay\createToken;

        $integrationKey = getenv('PONCHOPAY_INTEGRATION_KEY');
        $token = createToken($integrationKey, 'order-67651');
        ```
      </TabItem>
      <TabItem label="Shell">
        ```bash
        METADATA='order-67651'
        TOKEN=$(printf '%s' "$METADATA.$PONCHOPAY_INTEGRATION_KEY" \
          | openssl dgst -sha256 -binary | base64)
        ```
      </TabItem>
    </Tabs>
  </Fragment>
</ApiColumns>

## Parameters

<ApiColumns>
  Send the parameters as JSON (`Content-Type: application/json`) or as form data
  (`application/x-www-form-urlencoded` or `multipart/form-data`). In form data, use square
  brackets for nested values: `constraints[minimum_card_amount]=500`,
  `line_items[0][description]=Holiday club day`.

  <Fields schema="InitiatePayment" />

  <Fragment slot="code">
    <Tabs syncKey="lang">
      <TabItem label="Node.js">
        ```ts
        import { Client } from '@ponchopay/pp-nodejs';

        const client = new Client(process.env.PONCHOPAY_INTEGRATION_KEY);
        // Demo: new Client(key, 'https://demo.ponchopay.com/')

        // Computes the token and returns the checkout URL.
        const checkoutUrl = await client.initiatePayment({
          urn: 'INTTEST',
          amount: 1256, // £12.56
          metadata: 'order-67651',
          email: 'parent@example.com',
        });

        res.redirect(checkoutUrl); // e.g. Express
        ```
      </TabItem>
      <TabItem label="PHP">
        ```php
        <?php

        use PonchoPay\Client;

        $client = new Client(getenv('PONCHOPAY_INTEGRATION_KEY'));
        // Demo: new Client($key, 'https://demo.ponchopay.com/')

        // Computes the token and returns the checkout URL.
        $checkoutUrl = $client->initiatePayment([
            'urn' => 'INTTEST',
            'amount' => 1256, // £12.56
            'metadata' => 'order-67651',
            'email' => 'parent@example.com',
        ]);

        header('Location: ' . $checkoutUrl, true, 302);
        ```
      </TabItem>

## Returns

<ApiColumns>
  **`302 Found`**: the payment was created. Send the parent to the URL in the `Location` header.

  **`400 Bad Request`**: the payment wasn't created. The response says why. Common messages:

  | Message | What to check |
  | --- | --- |
  | `Invalid token or provider not setup` | The token was computed with the wrong key or different `metadata`, or the `urn` isn't one of your locations. |
  | `Minimum card amount can not be more than total amount` | `constraints.minimum_card_amount` is larger than `amount`. |
  | `Card payment method must be allowed when specifying a minimum card amount` | You set a minimum card amount but card payments aren't turned on for the provider. |
  | `Invalid body` | A parameter is missing or the wrong type, or the line items don't add up to `amount`. |

  <Fragment slot="code">
    ```http title="Response"
    HTTP/1.1 302 Found
    Location: <checkout URL for this payment>
    ```
  </Fragment>
</ApiColumns>

## What happens next

<ApiColumns>
  The parent pays on the PonchoPay checkout. As the payment progresses, PonchoPay sends
  [webhooks](/webhooks/overview/) to your callback URLs, each with your `metadata` so you can match
  it to your order. When checkout finishes, the parent is sent back to your **Payment completed**
  redirect URL, if you've set one.
