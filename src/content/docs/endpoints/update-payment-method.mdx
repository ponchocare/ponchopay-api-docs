<ApiColumns>
  Changes one payment method within a payment: its amount, its type, or both. Use it to correct
  how a payment was split, for example when a parent paid part of an invoice with vouchers instead
  of Tax-Free Childcare.

  The type can only change between `tax-free-childcare` and `childcare-voucher`. Changing the type
  cancels the old payment method and creates a new one with a new ID, which the
  [`payment_updated`](/webhooks/events/payment-updated/) webhook reports. PonchoPay sends
  `payment_updated` after any change.

  <Fragment slot="code">
    <Endpoint method="PUT" path="/api/payment-method/{paymentMethodId}" />
  </Fragment>
</ApiColumns>

## Authentication

<ApiColumns>
  Send a [management JWT](/getting-started/authentication/#management-jwt) in the `Authorization`
  header, with `sig` computed from the exact JSON body you send. The SDKs build the token for you,
  and take `urn` and `email` alongside the body fields.

  <Fragment slot="code">
    ```http
    PUT /api/payment-method/{paymentMethodId}
    Authorization: Bearer <jwt>
    Content-Type: application/json
    ```
  </Fragment>
</ApiColumns>

## Returns

<ApiColumns>
  **`204 No Content`**: the payment method was updated.

  **`400 Bad Request`**: nothing changed. Common messages:

  | Message | What to check |
  | --- | --- |
  | `Invalid amount` | `amount` is less than `1`. |
  | `Invalid scheme` | `type` isn't one of `card`, `childcare-voucher` or `tax-free-childcare`. |
  | `Invalid scheme change` | The type can only change between `tax-free-childcare` and `childcare-voucher`. |
  | `Voucher provider missing` | You changed `type` to `childcare-voucher` without a `voucher_provider`. |
  | `Invalid update` | The payment method is already in bank and can't be changed. |

  Payment methods of Express checkout payments, and payment methods that have been charged to the
  parent's card (for example through the payment guarantee), can't be updated: those requests are
  rejected too. A request that changes nothing returns `204` and sends no webhook. For a childcare
  voucher payment method, send its current `voucher_provider`, or the request counts as a change.

  An invalid or expired token is rejected before any of these checks.

  <Fragment slot="code">
    ```http title="Response"
    HTTP/1.1 204 No Content
    ```
  </Fragment>
</ApiColumns>
