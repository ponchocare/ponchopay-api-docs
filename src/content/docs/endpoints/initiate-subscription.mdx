<ApiColumns>
  Creates a recurring payment (subscription) for one of your locations, such as a monthly
  membership or termly fees, and redirects to the page where the parent sets it up. The response is
  a `302` redirect: send the parent to the URL in the `Location` header.

  If you include an `additional_one_time_payment`, for example a registration fee, the parent pays
  that first and then sets up the recurring payment.

  Like [Initiate a payment](/endpoints/initiate-payment/), you can call it from your server or post
  a form to it from the browser with the
  [`<pp-subscription>`](/sdks/browser/#pp-subscription)
  web component. Either way, your server computes the `token`.

  <Fragment slot="code">
    <Endpoint method="POST" path="/api/integration/generic/subscription/redirect" />
  </Fragment>
</ApiColumns>

## Authentication

<ApiColumns>
  Include a `token` field computed from your integration key and the request's `metadata`. See
  [initiation token](/getting-started/authentication/#initiation-token). The additional payment's
  `metadata` isn't part of the token.

  <Fragment slot="code">
    ```txt
    token = base64( sha256( metadata + "." + integrationKey ) )
    ```
  </Fragment>
</ApiColumns>

## Parameters

<ApiColumns>
  Send the parameters as JSON (`Content-Type: application/json`) or as form data
  (`application/x-www-form-urlencoded` or `multipart/form-data`). In form data, use square
  brackets for nested values: `repetition[granularity]=month`, `repetition[weekdays][]=monday`.

## Returns

<ApiColumns>
  **`302 Found`**: the recurring payment was created. Send the parent to the URL in the `Location`
  header. It's the additional payment's checkout if you sent `additional_one_time_payment`,
  otherwise the recurring payment set-up page.

  **`400 Bad Request`**: nothing was created. The response says why. Common messages:

  | Message | What to check |
  | --- | --- |
  | `Invalid token or provider not setup` | The token was computed with the wrong key or different `metadata`, or the `urn` isn't one of your locations. |
  | `Provider location not verified` | The location hasn't finished verification. Check with [Validate location](/endpoints/validate-location/). |
  | `Payments not enabled` | No payment methods are turned on for the provider. |
  | `The amount value is invalid` | `amount` isn't a valid amount in pence. |
  | `Invalid repetition` | `repetition` is missing a field its `granularity` needs, or has an unknown `granularity`. |
  | `Invalid ending` | `ending` is missing a field its `condition` needs, or has an unknown `condition`. |
  | `Consider an open-ending subscription` | `ending.date` is too far ahead. Use `"condition": "never"` instead. |
  | `Invalid body` | A parameter is missing or the wrong type. |

  <Fragment slot="code">
    ```http title="Response"
    HTTP/1.1 302 Found
    Location: <set-up URL, or the additional payment's checkout URL>
    ```
  </Fragment>
</ApiColumns>

## What happens next

<ApiColumns>
  When the parent leaves a card as a guarantee you get
  [`recurring_payment_captured`](/webhooks/events/recurring-payment-captured/). When everything
  needed to take payments is in place you get
  [`recurring_payment_set_up`](/webhooks/events/recurring-payment-set-up/), and the parent is sent to
  your **Subscription set up** [redirect](/redirects/subscription-set-up/) URL.
